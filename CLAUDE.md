# Pi-NOMAD: handoff notes for Claude Code

Offline-first knowledge server for a **Raspberry Pi 5 (4 GB, arm64), now booting from a 256 GB NVMe SSD (about 197 GB free)** inside a Pelican-case cyberdeck.
It is modeled on Project NOMAD (https://github.com/Crosstalk-Solutions/project-nomad) **without the AI stack**.
Owner: Mike, who runs a 3D printing and printer repair business in Wayne, Michigan. Keep answers plain and practical.

## Layout

- `compose.yaml`: stack: `command-center` (built from `./command-center`), `kiwix`, `flatnotes`, `cyberchef`, `files` (Dufs), `kolibri` (built from `./kolibri`), `mesh-bridge` + `meshmonitor` (Mesh Radio, port 8087).
- `command-center/`: Python **stdlib-only** web app on port 80.
  - `app.py` router and Range-capable `/maps-data/` file server; `zim.py` Kiwix catalog search, resumable downloads, `library.xml` writer; `maps.py` Protomaps region extracts via the `pmtiles` CLI; `jobs.py` background job registry.
  - `books.py` bookshelf: lists EPUB/PDF under `/data/books` (read-only mount), serves EPUB chapters straight out of the zip at `/books-read/<book>.epub/<member>` with a no-scripts CSP, PDFs at `/books-data/`. Pages: `static/books/index.html`, `static/books/read.html`. Tested with generated EPUB 2/3 files only, not real books yet.
  - `system.py` system panel (`/api/system`): reads `/proc` and `/sys` directly (host values are visible inside Docker). Checked on the real Pi 5 on 2026-11-12: `thermal_zone*/temp`, memory, uptime, disk and the `rpi_volt` hwmon `in0_lcrit_alarm` all read correctly. The firmware `get_throttled` file does not exist on this kernel (Debian 13), so throttle flags are never reported. `cooling_fan/hwmon/*/fan1_input` is unchecked because no fan is fitted.
  - `auth.py` optional admin PIN. No PIN set = everything open. PIN set = every POST except `/api/auth/unlock|lock` needs an unlocked session cookie (`nomad_admin`, 12 h, in memory); GETs stay open. Hash lives in the `nomad-config` volume at `/config/admin.json`. `static/auth.js` holds the `Admin` object (PIN dialogs, dashboard strip, styled with the theme's CSS variables, so the page must load `style.css`); `shared.js` `api()` prompts for the PIN on a 401 and retries. Any new endpoint that changes state must be a POST so it is covered.
  - `backup.py` Backup page (`static/backup.html`): copies `notes` and `books` to a USB drive into `pi-nomad-backup/<date_time>/`, or streams the notes as a zip (`/api/backup/download`). Libraries and maps are not copied; each backup has `installed-content.txt` listing them. Drives are found by reading `/proc/mounts` for mount points under `/media`, which compose binds in with `rslave` propagation. This relies on the Pi desktop session auto-mounting USB drives at `/media/nomad/<label>`; a headless Pi would need another way to mount. File names are made FAT-safe on the drive. A failed or cancelled backup removes its folder.
  - `search.py` one search box for everything (`/api/search?q=`, page `static/search.html`, box on the dashboard). Libraries come from kiwix-serve's own multi-ZIM search (`http://kiwix:8080/search?pattern=..&format=xml`, reached over the compose network; feed shape checked on 3.8.2). Notes are scanned as markdown files; books match on title, author and file name only. If kiwix answers 400 the search is retried with `books.filter.lang=eng`, because kiwix refuses one search across libraries in different languages (that retry is unit-tested only: every installed library is English). Note links use the flatnotes route `/note/<title>`.
  - `power.py` Shut down and Restart buttons on the dashboard (`/api/power`). The container cannot power the Pi off, so `install.sh` installs a host helper: `/usr/local/sbin/pi-nomad-power` plus `pi-nomad-power.path`/`.service` (systemd). The app writes `poweroff` or `reboot` to `/var/lib/pi-nomad/power/request` (bound in at `/power`); the path unit runs the helper, which deletes the file, waits 2 s and calls `systemctl`. Any other word is ignored. `helper-installed` in that folder tells the app the helper exists. The owner chose NOT to require the admin PIN for these buttons; they are a normal POST, so a PIN, once set, covers them like every other change.
  - `static/app.html` shows the Library, Notes, Data Tools or Files in an iframe under a slim bar with a Dashboard button, because those apps have no link home (`/app.html?app=library|notes|tools|files&path=/...`; only those four names and a plain path are accepted). Every link into those apps goes through `appUrl()` in `shared.js`. None of the four sends `X-Frame-Options` or `frame-ancestors` (checked 2026-11-14); if an image upgrade starts sending one, that app will show blank under the bar. The owner confirmed all four render on his PC; the built-in browser pane cannot show cross-origin frames, so it cannot be used to check this.
  - `places.py` place search on the map (`/api/maps/search?file=&q=&lon=&lat=`, box in `static/maps/index.html`). Fully offline: the names are read out of the `.pmtiles` file itself by a stdlib PMTiles v3 reader and a minimal vector-tile (protobuf) decoder, then kept in `<map>.places.db` (SQLite) beside the map. Towns come from zoom 12, streets, landmarks and water from zoom 14 (or the map's top zoom if lower), layers `places`, `roads`, `pois`, `water` of the Protomaps basemap. `kind_detail` (city/town/village/hamlet) decides the label and which places count as real towns for the "near ..." text. A `words` table makes lookups a few ms. The index is built after each extract and, at startup, for any map without a current one (shown as a job in Map regions). Measured on the Pi: Michigan detailed (1.1 GB, 735,000 names) indexes in about 65 s using 30 MB of memory, and the index file is 177 MB. If Protomaps renames layers or fields, search quietly finds less: re-check with a real map.
  - `services.py` Docker access: status lights (`states()`) and Stop / Start / Restart for the four other apps (`POST /api/services {service, action}`, Apps panel on the dashboard). It only acts on containers of this compose project named in `CONTROLLABLE` (kiwix, flatnotes, cyberchef, files) with `start|stop|restart`; the Command Center cannot stop itself. A stopped app stays stopped across reboots (`restart: unless-stopped`) until Start is pressed. The owner agreed to this after the risk was explained; do not widen the list of apps or actions without asking him.
  - `static/`: dashboard (`index.html`), Content Manager (`zim.html`), map viewer (`maps/index.html`), map region manager (`maps/manage.html`), bookshelf (`books/`). All share `style.css` (colours taken from the logo) and `shared.js`. `img/` holds the logo cut-outs and icons; `fonts/` bundles Outfit (OFL), so the design needs no internet.
  - `Dockerfile`: 3 stages: Go builds `pmtiles`; Node fetches maplibre-gl@5, pmtiles@4, @protomaps/basemaps@5 plus Protomaps fonts/sprites from GitHub; Python runs the app.
  - `tests/test_backend.py`: 68 unit tests. Run: `cd command-center && python3 tests/test_backend.py`
- `kolibri/Dockerfile`: Kolibri 0.19.5 from PyPI on `python:3.12-slim` (plus `iproute2`). There is no current upstream Docker image (Docker Hub ones are 6-7 years old). Data in `/srv/nomad/kolibri`. Ports 8085 (app) and 8086 (zipped interactive lessons) must be published with unchanged numbers. Kolibri sends `X-Frame-Options: DENY`, so its tile opens in a new tab and it is not in `app.html`. It has its own accounts and first-run setup, which the owner does himself. Measured on the Pi 2026-11-14 in a throwaway container: 60 s build, 4 s start, about 130 MB resident idle, image about 700 MB. Not measured: memory with lessons loaded and learners active.
- `tools/move-to-ssd.sh` moves the whole system from the SD card to an NVMe SSD (`--check` is a dry run; the real run needs sudo and the word ERASE). It repartitions the SSD like a Pi OS card (512 MB boot FAT32 + ext4), rsyncs `/` and `/boot/firmware` with the SD card only read, and rewrites the disk ID (`PARTUUID`) in the copy's `cmdline.txt` and `fstab`. Docker is stopped for the copy, so anything changed afterwards stays on the SD card only. The bootloader order is `0xf461` (SD, then NVMe, then USB), so the Pi boots from the SSD only when no SD card is fitted.
- `install.sh` (Docker + data dirs + `docker compose up -d --build`), `hotspot.sh` (Wi-Fi AP via NetworkManager).
- Data lives in `/srv/nomad/{zim,maps,notes,books,kolibri,mesh}`. Command-center mounts `zim` and `maps` writable, the rest read-only, plus the `nomad-config` volume at `/config`.
- `.gitattributes` forces LF line endings. Keep it: `install.sh` copied to the Pi with Windows line endings will not run.

## Hard constraints (verified 2026-11-08, don't break these)

- **Keep `ghcr.io/kiwix/kiwix-serve:3.8.2` pinned.** It uses libkiwix 14.2.1, which reads `library.xml` as `<library><book .../></library>`. Unreleased libkiwix `main` switches to an Atom/OPDS feed, which would make our library writer silently stop working. Attribute names we write were checked against `Book::updateFromXml` in libkiwix 14.2.1; `size` is KiB.
- The kiwix image's start script adds `--port` itself; it runs as uid 1001, so ZIMs must be world-readable.
- `ghcr.io/gchq/cyberchef` listens on 8080 inside the container. `files` (Dufs, which replaced the archived File Browser) must run as root to write to the root-owned data folder.
- kiwix-serve reloads `library.xml` only when its whole-second mtime increases, so `_write_library` always advances it.
- A note uploaded through Files is root-owned, so Notes can't save edits to it until the `flatnotes` container restarts (its start script fixes ownership).
- Kiwix catalog is `https://opds.library.kiwix.org/catalog/v2/entries` (the old host redirects). The `name=` filter is exact. One name can have several **flavours** (`nopic`, `mini`, `maxi`), so presets pick `(name, flavour)`. Download links are on `lb.download.kiwix.org` and end in `.zim.meta4` (strip it). Downloads are restricted to `*.download.kiwix.org`.
- `gutenberg_en_all` is 221 GB: never offer it. Wikipedia `nopic` is ~53 GB, `mini` ~14 GB, `maxi` ~127 GB.
- Protomaps daily builds: `https://build.protomaps.com/YYYYMMDD.pmtiles` (~139 GB planet; today's UTC build often 404s, so probe newest-first). They are compatible with `@protomaps/basemaps` 4 and 5. `pmtiles extract` has `--bbox`, `--maxzoom`, `--dry-run`. Fonts/sprites repo: `protomaps/basemaps-assets` (`fonts/`, `sprites/v4/light.*`).
- Every POST must carry `Content-Type: application/json` and, when the browser sends an `Origin`, it must match `Host` (`_from_our_pages` in `app.py`). This stops another website from making a browser on the LAN delete or download things. `shared.js` `api()` and `auth.js` already do this; curl needs `-H "Content-Type: application/json"`.
- Downloads are checked against the `<url>.sha256` file Kiwix publishes (verified live 2026-11-14 on `lb.download.kiwix.org`). A mismatch deletes the file; no checksum file means no check.
- Static files are served by `_static` in `app.py`: text types are gzipped (kept in memory by date and size), everything gets an ETag, and `/img/`, `/fonts/`, `/maps/lib/`, `/maps/assets/` may be cached by browsers for a day. After changing a file in those folders, a browser can show the old one for up to a day unless it is force-reloaded.
- Pages poll through `every()` in `shared.js`, which pauses while the tab is hidden.
- Versions are pinned on purpose: `go-pmtiles@v1.31.2` in the Dockerfile, `dullage/flatnotes:v5`, `ghcr.io/gchq/cyberchef:11` (v10 listens on port 80, v11 on 8080: pinning to `10` on 2026-11-14 took Data Tools offline until corrected), Kolibri 0.19.5, kiwix-serve 3.8.2, dufs v0.47.0. An install needs internet (it rebuilds two images).
- Successful GETs are not logged (dashboards poll every few seconds), and compose caps each container log at 3 x 5 MB.
- maplibre-gl **6.x is ESM-only**; we use 5.x because the viewer loads the UMD build with a plain `<script>`.
- Only a light admin PIN (see `auth.py`); the other apps (Files, Notes, Kiwix) are not behind it. Don't expose to the internet.
- Files is Dufs, which serves the data folder at its root: the books folder is `http://<pi>:8083/books/`.

Mesh Radio 2026-11-15: a Heltec WiFi LoRa 32 V4 (plain V4, USB ID `303a:1001`, shows up as `/dev/ttyACM0`, Meshtastic 2.7.10) is plugged into the Pi. `mesh-bridge` (`ghcr.io/yeraze/meshtastic-serial-bridge:1.1.4`, socat serial to TCP 4403) and `meshmonitor` (`ghcr.io/yeraze/meshmonitor:4.17.3`, about 470 MB resident) were installed through `install.sh`; MeshMonitor synced 14 nodes from the radio, answers on every address, and recovered by itself when only the bridge was restarted. Things learned the hard way:
- The bridge shares all of `/dev` with `device_cgroup_rules` for majors 166 and 188, and reads `/dev/pi-nomad-radio`, a udev symlink `install.sh` creates for common Meshtastic USB vendors. A fixed `devices:` entry would stop the container from starting when the radio is unplugged.
- MeshMonitor answers 500 to any browser address not in `ALLOWED_ORIGINS`; `*` works. `COOKIE_SECURE=false` is needed on plain HTTP. `IFRAME_ALLOWED_ORIGINS=*` replaces its `X-Frame-Options: DENY`, which is why it can sit in `app.html`.
- MeshMonitor keeps the radio's address in its database (`sources.config`), seeded from `MESHTASTIC_NODE_IP` only on first run. Renaming the bridge service later means editing that row or the Sources page.
- Once, right after the reinstall, the sync stalled with no data until bridge and MeshMonitor were restarted in that order; the radio had re-enumerated on USB. Not reproduced since.
- `docker stats` shows 0 B on this Pi (memory cgroup off); use `docker top <name> -o pid,rss,comm`.
Not tested: login while inside the top-bar frame (owner's account), sending, unplug/replug, offline map, GPS.

## Working style

- Verify against real sources before claiming something works; say plainly what wasn't tested.
- Keep the command-center dependency-free (stdlib only) unless there is a strong reason.
- Add or update a unit test with every backend change.
- Commits: author them as the repo owner (`redneck3d`, GitHub noreply email). Do not add `Co-Authored-By: Claude` or any other Claude/AI attribution lines to commit messages or pull requests.
